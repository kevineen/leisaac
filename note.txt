# LeIsaac 作業メモ（学習用 PC）

最終更新: 2026-09-06

## 運用方針（重要）

- **公式（LightwheelAI/leisaac）へはプルリクを出さない。**
- 改造・実験・日常の更新は **すべて自分の fork（kevineen/leisaac）だけで続ける。**
- 公式の更新は、**大幅なアップデート（リリース・breaking change・欲しい機能）のときだけ** `upstream/main` から取り込む。
- 細かい本家コミットを毎回追わない。取り込み頻度より、自分の改造が壊れないことを優先する。

流れのイメージ:

```text
日常:   自分の fork で改造 → origin に push
ときどき: upstream/main（公式）を確認 → 必要なときだけ merge → origin に push
```

## 日常の改造（自分の fork だけ）

### 1. 作業ブランチを切る

main 直編集は避ける。

```bash
cd ~/robot/leisaac
git checkout main
git pull origin main
git checkout -b feat/<短い名前>
# 例: feat/training-pc
```

### 2. 改造の優先順位（学習 PC 向け）

1. Installation をこの PC の GPU / 環境に合わせる
   https://lightwheelai.github.io/leisaac/docs/getting_started/installation
2. 依存の lerobot を自分の fork（~/robot/lerobot）に向ける
3. データ・モデル保存先を決める（例: /mnt/shared_hdd/...）
4. 必要なら環境・タスク・変換スクリプトを追加
5. 学習結果をラズパイへ渡す手順を README かこの note に追記

### 3. コミット & push（origin のみ）

```bash
git status
git add <変更ファイル>
git commit -m "変更の理由を短く"
git push -u origin HEAD
```

必要なら自分の fork 内で PR（`feat/*` → `main`）を作ってもよい。**本家向け PR は作らない。**

### 4. 自分の main に取り込む

```bash
git checkout main
git merge feat/<名前>
git push origin main
```

## 公式の大幅アップデートを取り込む

こまめな追従はしない。次のようなときだけ取り込む。

- 公式が大きなバージョンアップをした
- 欲しい機能・ロボット・ポリシー対応が増えた
- 依存（Isaac Lab / LeRobot）の互換が大きく変わった

### 取り込む前

```bash
cd ~/robot/leisaac
git fetch upstream

# 公式 main がどれだけ進んだか確認
git log --oneline main..upstream/main | head -50

# リリースノートや README / News も見る
# https://github.com/LightwheelAI/leisaac/releases
# https://github.com/LightwheelAI/leisaac/blob/main/README.md
```

差分が大きい・怖いときは、取り込み専用ブランチで試す。

```bash
git checkout main
git pull origin main
git checkout -b sync/upstream-$(date +%Y%m%d)
git merge upstream/main
# コンフリクト解消・動作確認
# 問題なければ main に merge して origin へ push
git checkout main
git merge sync/upstream-$(date +%Y%m%d)
git push origin main
```

問題なさそうなら main に直接 merge してもよい。

```bash
git checkout main
git pull origin main
git merge upstream/main
# コンフリクトがあれば解消 → commit
git push origin main
```

### 取り込み時の注意

- 自分の改造（パス・依存・独自スクリプト）が衝突しやすい。先にバックアップブランチを切ると安全。
  `git branch backup/before-upstream-$(date +%Y%m%d)`
- 衝突したら公式側を盲目的に優先せず、**自分の学習 PC 用改造を残すか**を判断する。
- 取り込み後は、インストール手順・学習が一通り通るか確認してから次の改造に進む。
- 大きなファイル・データセット・学習成果物は git に入れない（.gitignore を確認）。

## Python 環境（Miniconda）

**uv は使わない。** LeIsaac / Isaac Lab 公式は conda 前提。この PC は Miniconda。

```text
インストール先: ~/miniconda3
環境名:
  leisaac       Python 3.11 … Isaac 用（NVIDIA 差し替え後。いまは空に近い）
  lerobot-rocm  Python 3.12 … 学習用（Radeon / ROCm。kevineen/lerobot を editable）
```

起動（新しいシェルでも）:

```bash
# bashrc に conda init 済み。初回だけ再ログイン or:
source ~/miniconda3/etc/profile.d/conda.sh

# 学習（Radeon）
conda activate lerobot-rocm
python --version   # 3.12.x であること

# Isaac（NVIDIA 差し替え後）
conda activate leisaac
python --version   # 3.11.x であること
```

公式 Install from Source の残りは **今は実行しない**（R9700）。手順は「B: Isaac Sim」の差し替え後セクションに集約した。

### GPU 方針（確定）

- **現状**: AMD Radeon AI PRO R9700（ROCm / gfx1201）。
- **学習 (A / C)**: `lerobot-rocm` で可。PyTorch `2.11.0+rocm7.14.1`（gfx1201 wheel）。デバイス名は ROCm でも `cuda`（`--policy.device=rocm` も `cuda` に正規化）。
- **Isaac Sim (B)**: 動かない。CUDA / isaacsim / `isaaclab.sh --install` は **NVIDIA 差し替えまで入れない**。既存 `leisaac` env に ROCm torch を混ぜない。手順は次節。
- **lerobot 本格 ROCm 対応 (C)**: `feat/rocm-train`。device_utils の ROCm 明示、groot は flash-attn スキップ / SDPA、torchcodec は **入れない**（PyAV）。

#### B: Isaac Sim（この PC では動かない）

Isaac Sim / Isaac Lab は NVIDIA GPU + CUDA 前提。R9700 / ROCm では起動しない。
**MuJoCo など別シミュレータへの置き換えはしない**（LeIsaac のタスク・USD・変換経路の価値が落ちるため）。

取れる道は次の2つ。併用してもよい。

##### 1. 推奨運用: 別 NVIDIA 機 / クラウドで Sim、この PC は学習のみ

```text
[NVIDIA 機 or クラウド]
  conda env leisaac (Python 3.11)
  Isaac Sim / Isaac Lab で収集 → HDF5
  isaaclab2lerobotv3.py で LeRobot Dataset 化
  成果を共有 HDD or rsync / Hub へ

[この PC / R9700]
  conda env lerobot-rocm (Python 3.12)
  HF_LEROBOT_HOME=/mnt/shared_hdd/robot/datasets/lerobot
  lerobot-train（ACT / SmolVLA / diffusion / pi …）
  CKPT は ROBOT_MODELS_CHECKPOINTS → ラズパイへ
```

別機側の要点:

- `MACHINE_ROLE=training` / `GPU_VENDOR=auto`（NVIDIA なら Isaac が有効）。
- データルートを揃える（同じ `ROBOT_DATA_ROOT` か、変換後だけこの PC の HDD へコピー）。
- 学習は **この PC の `lerobot-rocm`** で行う（別機で CUDA 学習してもよいが、fork の ROCm 改造はこちらが本体）。
- クラウド例: NVIDIA GPU 付き VM に同じ `kevineen/leisaac` を clone → 下の「差し替え後の再開手順」と同じインストール。

受け渡し例:

```bash
# 別機 → この PC（データセットだけ）
rsync -avh --progress user@nvidia-box:/mnt/data/robot/datasets/lerobot/my_task/ \
  /mnt/shared_hdd/robot/datasets/lerobot/my_task/
```

##### 2. この PC を NVIDIA に差し替えたあとの再開手順

差し替え後も `.env.local` の `GPU_VENDOR=auto` のままでよい。`source scripts/env/load_env.sh` し直すと `ISAAC_SUPPORTED=1` になる想定。

```bash
# 1) ドライバ
nvidia-smi   # 失敗したらプロプライエタリ NVIDIA ドライバを入れて再起動

# 2) Isaac 用 env（Python 3.11）。ROCm torch は入れない

cd ~/robot/leisaac

# 3) 動作確認
```

差し替え後も学習は `lerobot-rocm` のままでよい（Radeon を外すなら CUDA の lerobot env を別途作る）。Sim 収集だけ `leisaac` env。

**今の R9700 のままでは上記を実行しない。** `leisaac` env に CUDA wheel を入れると壊れる。

#### 学習 env の使い方（`lerobot-rocm`）

公式 PyPI の `lerobot` は使わない。自分の fork（`~/robot/lerobot` / origin: kevineen）を editable で入れる。ブランチ: `feat/rocm-train`。

```bash
source ~/miniconda3/etc/profile.d/conda.sh
conda activate lerobot-rocm

# llama.cpp 等が VRAM を占有していると OOM になる。学習前に止める。
# 例: pgrep -af llama-server

export HF_LEROBOT_HOME=/mnt/shared_hdd/robot/datasets/lerobot
export WANDB_MODE=disabled
export TORCH_BLAS_PREFER_HIPBLASLT=0   # gfx1201 の hipblasLt 警告回避

python -c "import torch, lerobot, inspect; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0)); print(inspect.getfile(lerobot))"
# 期待: 2.11.0+rocm7.14.1  True  AMD Radeon AI PRO R9700
#       /home/kevin/robot/lerobot/src/lerobot/__init__.py
```

再インストール（torch は AMD index を忘れない）:

```bash
conda activate lerobot-rocm
pip install --index-url https://repo.amd.com/rocm/whl-multi-arch/ \
  "torch[device-gfx1201]==2.11.0+rocm7.14.1" \
  "torchvision[device-gfx1201]==0.26.0+rocm7.14.1"
pip install "numpy>=2.0.0,<2.3.0"
pip install -e "/home/kevin/robot/lerobot[training,smolvla]" \
  --extra-index-url https://repo.amd.com/rocm/whl-multi-arch/
```

スモーク確認済み（2026-09-06）:

```bash
# ACT 50 step → CKPT: /mnt/shared_hdd/robot/models/checkpoints/act-rocm-smoke
# SmolVLA 10 step → CKPT: /mnt/shared_hdd/robot/models/checkpoints/smolvla-rocm-smoke
# diffusion 10 step → CKPT: /mnt/shared_hdd/robot/models/checkpoints/diffusion-rocm-smoke
```

追加スモーク:

```bash
# diffusion extra
pip install -e "/home/kevin/robot/lerobot[training,diffusion]" \
  --extra-index-url https://repo.amd.com/rocm/whl-multi-arch/

lerobot-train \

  --output_dir=/mnt/shared_hdd/robot/models/checkpoints/diffusion-rocm-smoke \
  --steps=10 --batch_size=4 --num_workers=2 --log_freq=5 \
  --eval_freq=0 --save_freq=10 --wandb.enable=false

# pi extra は入る。pi0 学習は google/paligemma-3b-pt-224 が gated。
# HF にログインしてアクセス許可したあと:
# pip install -e "/home/kevin/robot/lerobot[training,pi]" --extra-index-url https://repo.amd.com/rocm/whl-multi-arch/
# huggingface-cli login
lerobot-train \
  --policy.type=pi0 \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --dataset.repo_id=lerobot/pusht \
  --dataset.video_backend=pyav \
  --output_dir=/mnt/shared_hdd/robot/models/checkpoints/pi0-rocm-smoke \
  --steps=5 --batch_size=1 --num_workers=0 --log_freq=1 \
  --eval_freq=0 --save_freq=5 --wandb.enable=false
```

注意:

- `torchcodec` は **入れない**（PyPI は CUDA ABI。ソースビルドもしない）。動画は fork の **native PyAV**。
- `--policy.device=cuda` でよい。`rocm` と書いても内部で `cuda` に正規化される。
- groot は `flash-attn` を入れない。ROCm では SDPA。CUDA 機だけ任意で `pip install flash-attn`。
- ROCm torchvision には `VideoReader` が無い。
- llama.cpp（Qwen 27B 等）と同時に GPU 学習すると VRAM 不足。どちらか一方。
- HDF5→LeRobot 変換（`isaaclab2lerobotv3.py`）は Isaac 必須。データは別 NVIDIA 機 / Hub / 実機 `lerobot-record`。

## データ・モデル保存パス / マシン設定（.env.local）使い方

大容量は git 外の共有 HDD に置く（作成済み）。**マシンごとのパス・役割・GPU は `.env.local` で管理する**（`.gitignore` 済み・git に乗せない）。

関連ファイル:

| ファイル | 内容 |
|----------|------|
| `.env.example` | テンプレート（git 管理） |
| `.env.local` | このマシン専用の実設定（git 外） |

| `scripts/env/show_env.sh` | 解決結果を表示するだけ |
| `source/leisaac/leisaac/utils/machine_config.py` | Python 用の同設定 |

### 1. 初回セットアップ

```bash
cd ~/robot/leisaac
cp .env.example .env.local    # この PC では作成済みなら不要
```

### 4. GPU の自動切替

`.env.local` で `GPU_VENDOR=auto`（推奨）。起動時にハードを見て解決する。

| 判定 | `GPU_BACKEND` | `leisaac_gpu_smi` | Isaac (`ISAAC_SUPPORTED`) |
|------|---------------|-------------------|---------------------------|
| NVIDIA | nvidia | `nvidia-smi` | 1（`MACHINE_ROLE=training` 時） |
| AMD Radeon / ROCm | amd | `rocm-smi` | 0（Sim は保留。学習は `lerobot-rocm`） |
| なし（ラズパイ等） | none | （失敗） | 0 |

手動固定したいとき: `GPU_VENDOR=nvidia` / `amd` / `none`。
Isaac を無理に有効/無効にするとき: `ISAAC_ENABLED=true` / `false`（通常は `auto`）。

この PC の現状: **AMD → `ISAAC_SUPPORTED=0`**（Sim 不可）。学習は `conda activate lerobot-rocm`。NVIDIA 差し替え後は `auto` のまま再 `source` すれば Isaac が `1` になる想定。

### 5. Python から使う

```python
from leisaac.utils.machine_config import ensure_machine_env

cfg = ensure_machine_env()
print(cfg.robot_data_root)
print(cfg.datasets_lerobot)
print(cfg.gpu_backend, cfg.isaac_supported)
```

`leisaac.utils.constant.ASSETS_ROOT` も `.env.local` の `LEISAAC_ASSETS_ROOT` を自動で拾う。

## lerobot fork との接続

| 項目 | 値 |
|------|-----|
| ローカル | `~/robot/lerobot` |
| origin | `kevineen/lerobot` |
| upstream | `huggingface/lerobot` |
| 学習ブランチ | `feat/rocm-train`（kevineen/lerobot。本家 PR しない） |
| fork の版 | **0.5.2** / `requires-python >=3.12` |
| LeIsaac 公式 optional | `lerobot==0.4.2`（PyPI）← **使わない** |

方針: `pip install -e "source/leisaac[lerobot]"` は使わず、**自分の fork を `lerobot-rocm` に editable インストール済み**。

```bash
conda activate lerobot-rocm
pip install -e "/home/kevin/robot/lerobot[training,smolvla]" \
  --extra-index-url https://repo.amd.com/rocm/whl-multi-arch/
```

### 残っている互換ギャップ（Isaac 接続）

1. **Python 二系統**: Isaac は 3.11（`leisaac`）、学習は 3.12（`lerobot-rocm`）。混ぜない。
2. **版**: 公式 LeIsaac は 0.4.2 想定、fork は 0.5.2。Isaac 推論接続時に API 差分が出たら合わせる。

C（ROCm 学習コア）は `feat/rocm-train` で実装済み:

- `device_utils`: ROCm 明示ログ、`rocm`/`hip` → `cuda`、AMP は `cuda:N` 対応、attn は SDPA フォールバック
- groot: flash-attn を extra から外し、Eagle は SDPA
- torchcodec: extra に入れない。デフォルトデコーダは PyAV

## トラブルシュート

| 症状 | 対処 |
|------|------|
| push で Authentication failed (HTTPS) | origin を SSH URL にしているか確認。ssh-add する |
| Permission denied (publickey) | ssh-add ~/.ssh/id_ed25519 → ssh -T git@github.com |
| upstream merge で衝突 | 衝突ファイルを手で直し、自分の改造を残すか判断 → git add → git commit |
| 取り込みで壊れた | `backup/before-upstream-*` に戻すか、sync ブランチを捨ててやり直す |
| 巨大ファイルを誤って add | commit 前に git reset。必要なら .gitignore に追加 |
| 誤って本家向け PR を作りそう | 作らない。push 先は常に origin（kevineen/leisaac） |
| `.env.local` が無い / パスがリポジトリ内のまま | `cp .env.example .env.local` → 編集 → `source scripts/env/load_env.sh` |
| `leisaac_env_info` が未定義 | 先に `source scripts/env/load_env.sh` する |
| GPU 判定が違う | `.env.local` で `GPU_VENDOR=nvidia` または `amd` に固定 |
| 別ドライブに切り替えたのにパスが戻る | `VAR=... source` は使わず `leisaac_use_data_root` か `.env.local` を編集 |
| 学習が CUDA OOM（VRAM 0 bytes free） | llama.cpp / LM Studio が GPU を占有していないか。`pgrep -af llama-server` → 止めてから再実行 |
| `torchvision.io.VideoReader` が無い | ROCm torchvision の制限。`--dataset.video_backend=pyav`（fork の native PyAV） |
| `pip` が公式 CUDA torch に戻す | `--extra-index-url https://repo.amd.com/rocm/whl-multi-arch/` を付ける。`leisaac` env に ROCm torch を入れない |
| `flash-attn` が入らない / undefined symbol | ROCm では入れない。groot は SDPA。CUDA 機だけ任意インストール |
| `torchcodec` で落ちる | 入れない。uninstall して `video_backend=pyav` |
| Isaac Sim が起動しない（R9700） | 仕様。別 NVIDIA 機か差し替え後。MuJoCo 置き換えはしない |
| pi0 が gated repo で落ちる | `google/paligemma-3b-pt-224`。HF で許可 → `huggingface-cli login`。ROCm とは別件 |
